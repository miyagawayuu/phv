[English](security-audit.md) | 日本語

この報告は 17 回の監査をまとめたもの。§1〜§6 が 1 回目(と残存リスクの解消)、§7 が 2 回目の脆弱性診断、
§8 が 2 回目で対象外にした部分(`phv lsp`、`phv migrate`、バイトコードキャッシュ)の診断、§9 が v0.4.0 までに追加したものの診断、§10 が残存リスクへの対応、§11 が v0.5.0 で追加したものの診断、§12 がその残存リスクへの対応、§13 が v0.5.2 で追加したものの診断、§14 が v0.6.0 で追加したものの診断、§15 が v0.7.0 で追加したものの診断、§16 が圧縮するプロキシへの対応(v0.7.1)、§17 が v0.8.0 で追加したものの診断、§18 が v0.9.0 で追加したものの診断、§19 と §20 が v0.9.0 の 2 回の外部レビューへの対応(v0.9.1)、§21 が 1.0 の作業を始める前の実装全体の診断、§22 が 1.0.0 の前の実装全体の診断、§23 が処理の改善のあとの実装全体の診断、§24 が 1.1.0 の前の実装全体の診断、§25 が 1.1.1 の前の実装全体の診断、§26 が 1.2.0 の前の実装全体の診断、§27 が 1.2.0 のリリース候補の実装全体の診断。

実施日: 2026-11-02(§9〜§13: 2026-11-03、§14〜§19: 2026-11-04、§20〜§22: 2026-11-05、§23〜§25: 2026-11-06、§26〜§27: 2026-11-07)
対象: PHV 処理系のすべてのクレート(構文解析・型検査・コンパイラ・VM・JIT・標準ライブラリ・Web サーバー・CLI ツール)

## 1. 方法

1. **独立した 3 つのレビュー**。実装者の前提に引きずられないよう、担当を分けた 3 人のレビュアーがソースを読み、
   実際に攻撃コード(PoC)を動かして確かめた。
   - A: HTTP 層(ルーティング、静的ファイル、セッション、CSRF、multipart、ヘッダー)
   - B: ランタイム(VM、JIT、メモリ・時間の上限、標準ライブラリ、ファイル権限、SQLite)
   - C: 言語の保証とツール(エスケープ、型システムの健全性、`Html`/`Sql` 型、モジュール読み込み、`phv install`/`migrate`/`lsp`)
2. **修正と再検証**。すべての指摘を修正し、レビュアーが残した PoC を修正後のビルドでもう一度実行した。
3. **自動テスト**。ゴールデンテストに回帰テスト(`tests/cases/err_security.phv`、`security.phv`)を追加した。
   ほかに、実サーバーへの HTTP 結合テストと、変異させたプログラムによるファジング(ローカルで約 22,000 件)を
   CI で常に実行する。

## 3. 指摘と対応

### Critical

| # | 内容 | 対応 | 確認 |
|---|---|---|---|
| C1 | Windows で `/INDEX.PHV`、`/index.phv::$DATA`、8.3 短縮名 (`/DASHBO~1.PHV`、`/ENV~1`) のような別名で、`.phv` のソース・テンプレート・ドットファイルがそのまま配信された | 正規化したパスの各要素が、要求されたパスと**完全に同じ綴り**のときだけ配信する。`:` を含むパスは拒否。`.phv` / `.phv.html` / `.` で始まるファイルは静的ファイルとして扱わない | 実サーバーで全パターン 404、単体テストに追加 |
| C2 | 30 万段入れ子の list を捨てると再帰的な解放でスタックが溢れ、サーバープロセスごと落ちた(`catch_unwind` では止められない) | `Value` の解放と `==` の比較を反復処理にした | 100 万段で正常終了(テスト `deep_values_do_not_overflow_the_stack`) |
| C3 | `"a"->padStart(10^13, "b")` のような巨大確保の失敗でプロセスが abort した | 出力が入力より大きくなり得る組み込み関数は、確保する前に `reserve()` で上限を確認する(pad、repeat、replace、chars、split、join、concat、range、ファイル読み込み、文字列連結) | 捕捉できない致命的エラー(メモリ上限)になり、プロセスは生きている |

### High

| # | 内容 | 対応 | 確認 |
|---|---|---|---|
| H1 | ジェネリックの型引数を `is` で絞り込むと `never` になり、任意の値を `Sql` や `Html` として通せた(SQL インジェクション、`raw()` を使わない XSS) | 型引数・`any` の絞り込みは検査対象の型にする。interface や `Sql` を考慮し、結果が `never` になる絞り込みは適用しない。`Html` の連結は実行時にも素の文字列をエスケープする | PoC はコンパイルエラーになる |
| H2 | `&&` / `\|\|` の右辺や `render()` の中で呼び出しがあっても、プロパティの絞り込みが残った | 呼び出しのたびに世代番号を進め、呼び出しをまたいだプロパティの事実は捨てる | PoC 4 件ともコンパイルエラー |
| H3 | `public/` の `.php` などが生のまま配信された | 静的ファイルは既知の拡張子(css、js、画像、フォント など)だけを配信する | `/config.php` は 404 |
| H4 | 匿名の GET で CSRF トークンのためにサーバー側セッションが作られ、10 万件で満杯になり、新しい訪問者がログインやフォーム送信をできなくなった | CSRF トークンを「ブラウザごとのランダムな Cookie の HMAC」にして、サーバー側に状態を持たない。セッション保存領域は件数とバイト数の上限付きで、古いものから追い出す | 単体テスト(上限を超えても新しい訪問者がセッションを得られる) |
| H5 | ヘッダー・本文の受信にタイムアウトがなく(slowloris)、接続数の上限もなかった | ヘッダー 10 秒(keep-alive の待ち時間も含む)、本文 30 秒、同時接続 1024 | 途中までのヘッダーは 10 秒で切断 |
| H6 | メモリ上限が組み込み関数の中ではほとんど効いていなかった | 組み込み関数の呼び出しのたびに確認、確保前の `reserve()`、SQLite の文字列長・ヒープ上限 | 16 MB の設定で 1 GB 確保の PoC が止まる |
| H7 | SQLite のクエリが実行時間の上限を無視した | SQLite の progress handler で上限時刻に中断する | 無限の再帰 CTE が 2 秒で止まる |
| H8 | 実行時間の上限が命令数で数えられていて、遅い組み込み関数を繰り返すと何倍も延びた | 組み込み関数の呼び出しのたびに時刻を確認する | |
| H9 | 書き込み可能なディレクトリに置かれた「リンク先が存在しない」シンボリックリンク経由で、サンドボックスの外にファイルを書けた | シンボリックリンクとリパースポイント(ジャンクション)を拒否し、解決済みのパスで操作する | リンクもジャンクションも拒否 |

### Medium

| # | 内容 | 対応 |
|---|---|---|
| M1 | エスケープが文脈を見ていなかった(引用符なしの属性、`href="javascript:..."`、`<script>`、`<style>`、イベント属性) | `<?= ?>` の位置の HTML 文脈を構文解析時に判定し、安全でない場所への文字列の挿入をコンパイルエラーにする。`safe_url()` と `json_html()` を追加 |
| M2 | `response()->type("image/svg+xml")` や `"text/plain, text/html"` でエスケープが外れた | エスケープを外すのは許可リスト(`text/plain`、`application/json`、`text/csv` など)の型だけ。カンマを含む Content-Type は拒否 |
| M3 | `render()` が `.env` などプロジェクト内の任意のファイルを読めた。ジャンクションでプロジェクトの外も読めた | テンプレートは `.phv.html` だけ。正規化したパスがプロジェクトかパッケージの中にあることを確認する |
| M4 | `phv install` が既存の `vendor/<名前>/.git` の中で git を実行し、同梱された hook が動いた | 毎回一時ディレクトリに新しく clone し、hook・fsmonitor を無効にし、プロトコルを許可リストで制限する。lock のコミットは 40 桁の 16 進数だけを受け付ける |

| M6 | スクリプトが `Content-Length` などを設定でき、keep-alive のレスポンスがずれた(レスポンス分割) | 通信の枠組みに関わるヘッダーは組み込み関数とサーバーの両方で拒否する |
| M7 | 開発モード(エラー詳細の表示)が既定だった | 既定で開発モードになるのはループバックで待ち受けるときだけ。`--dev` / `--prod` で明示できる |
| M8 | SQLite の `PRAGMA temp_store_directory` などでプロセス全体の設定を変えたり、ほかのディレクトリに書いたりできた | authorizer で `ATTACH`/`DETACH` と危険な pragma を拒否する |
| M9 | 範囲外の `slice()` で内部パニックが起きた | 飽和演算にした。リリースビルドでも整数オーバーフローを検査する |
| M10 | アップロードを `.phv` として保存したり、`write = ["."]` でソースを書き換えたりできた | `.phv` は書き込めない。`public/` 配下やプロジェクトのルートは `[permissions].write` に指定できない |

### Low / Info(主なもの)

- **アップロードのファイル名**: `:`、Windows の予約名、末尾のドットを除去する(修正)。
- **セッション**: ログイン(`regenerate()`)で CSRF の Cookie も更新、24 時間の絶対有効期限、HTTPS では `__Host-` 接頭辞と HSTS。
  セッションのあるレスポンスには `Cache-Control: private, no-store` を付ける(修正)。
- **リダイレクト**: `redirect()` はサイト内のパスだけ。外部へは `redirectExternal()`(オープンリダイレクト対策)。
- **パスの依存パッケージ**: 絶対パスと UNC パスは指定できない。開いただけで SMB 接続が起きるのを防ぐ(修正)。
- **bytecode キャッシュ**: JIT は読み込んだバイトコードのレジスタ・ジャンプ・呼び出しの範囲を検証する(修正)。
  キャッシュ自体はソースコードと同じ信頼レベルとして扱う(仕様として受容)。
- **`password_verify`**: 保存されたハッシュのコスト値に上限を設けた(修正)。
- **その他**: `_` で始まるファイルはページとして公開しない。ステータス 1xx は拒否する。JSON の `\u` を厳密に解釈する。
  LSP のヘッダー長を制限し、UNC の URI を拒否する。いずれも修正済み。

| N1 | (今回見つかった、Medium)`file_put_contents("data/a.phv::$DATA", ...)` や `"data/b.phv."` で、`.phv` の書き込み禁止をすり抜けて `a.phv` を作れた。`CON` などのデバイス名も使えた | パスの各要素について、`:`、末尾のドット・空白、`CON` `NUL` `COM1` `LPT1` などのデバイス名、制御文字を拒否する(すべての OS で同じ規則) | 3 つの PoC とも `PermissionError` |
| R3 | CSP が既定でオフだった | 既定で有効にした。テンプレートに書いた `<script>` タグには、構文解析の時点で位置を記録しておき、レスポンスごとの nonce を自動で付ける。`raw()` などで注入された `<script>` には付かないので動かない | HTTP 結合テストで、ヘッダーの nonce とテンプレートの 2 つの `<script>` が一致し、`raw()` の `<script>` には付かないことを確認。サンプルサイトはブラウザで動作 |

| R5 | セッションがメモリ内だけだった | `[security] session_store = "dir/"` でファイルに保存。ファイル名は ID の SHA-256(一覧から ID が分からない)、書き込みは一時ファイルからの rename で原子的、読み書きは `safefs` 経由。件数・容量の上限と期限切れの掃除あり | 別のサーバープロセスから同じセッションを読めることを HTTP 結合テストで確認 |

## 7. 2 回目の脆弱性診断

実施日: 2026-11-02(1 回目の修正と残存リスクの解消の後)

### 方法

1 回目の結論に引きずられないよう、新しいレビュアー 4 人にソースだけを渡し、それぞれ実際に攻撃して確かめた。

- A: 1 回目の後に書いたコード(`safefs`、ファイル保存のセッション、レート制限、CSP の nonce)
- B: Web サーバーとサンプルサイト(外からの攻撃)
- C: テンプレートの文脈判定と型システム
- D: SQL、実行時の上限、JIT、バイトコードキャッシュ、ツール

ほかに、依存クレートを `cargo audit` で調べた(既知の脆弱性 0 件。保守されていない `atomic-polyfill` を
postcard の既定機能を外して取り除いた)。`unsafe` のコードと CI の設定も読んだ。修正の確認では、
レビュアーが残した PoC を修正後のビルドでもう一度実行し、回帰テストに加えた。Linux(Docker)でも全テストを実行した。

## 16. 追加の対応: 圧縮するプロキシ(v0.7.1)

実施日: 2026-11-04。v0.7.0 をデモに配備したあと、Fly.io 経由でページを確かめると、CSRF トークンを含み PHV は圧縮せずに
送る(§15 の R8-1)`/board` が圧縮されて届いた。Fly.io のプロキシは、アプリが `Content-Encoding` ヘッダーを付けずに送った
レスポンスをすべて圧縮し、ほかのプロキシや CDN も同じことをしうる。そのため、訪問者ごとのレスポンスを圧縮しないという
PHV の規則は、そうしたプロキシの後ろではそれらを守れない。

| # | 内容 | 修正 |
|---|---|---|
| R9-1(中) | 圧縮するプロキシの後ろでは、ページの CSRF トークンがリクエストの文字列と並んで圧縮され、その大きさからトークンが推測されえた(BREACH) | `csrf_field()` と `csrf_token()` は、書くたびに別の乱数でトークンをマスクする(乱数、続いてトークンと乱数の XOR: 16 進数 128 桁)。サーバーは比べる前にマスクを外し、そのままの形のトークンも受け付ける(もうどこも書かない) |

プロキシがサーバーの規則を打ち消しうることと、そうしたページではプロキシの圧縮を止めることを書いた。

`X-CSRF-Token` でも)とそのままのトークンは受け付けられ、空、短い、長い、16 進数でない、ASCII でない値、乱数を自分自身と
組にしたもの、別のセッションのトークン、`regenerate()` 前のトークンは拒まれ、どの入力でもサーバーは異常終了しなかった。

  いる。見積もりは 1 秒に約 10^8 ステップ(診断者のマシンの約 75%)としているので、数倍遅いマシンでは検索が制限時間を
  数秒過ぎて終わることがある。

### 検証

すべての PoC を修正したビルドで再実行した。64 MB の制限のもとで、整形した JSON、`flatten`、`flatMap`、`csv_encode`、
`chunk`、正規表現の呼び出しは制限で止まる(最大 2〜78 MB、入力を含む。以前は 0.4〜3.5 GB)。NaN の並べ替えは動き、
readonly のクラスは拒否され、標準入力の 600 MB は制限で止まる。サイトに対して: 元のパターンと 1 MB の本文は 80 ms で
拒否され、状態が 4,000 のパターンと 500 KB の本文は 14 秒で、30 秒の制限内に終わる。整形・平坦化・フォーム検索のページは制限で 500 を返し、サーバーは約 7 MB のまま。300 個の異なるパターンの
あとも 15 MB。回帰テスト: `crates/phv_driver/tests/limits.rs`(16 MB の制限のもとでのすべての組み立てと正規表現の
呼び出し、2 秒の制限のもとで拒否される検索)、`re.rs`・`textio.rs`・`crypt.rs` の単体テスト、
`tests/cases/collections2.phv`(NaN)、`err_json_as.phv`(readonly)、`files_and_directories`(`./`)。問題がなかった
もの: リンク・ジャンクション・ハードリンク・ストリーム名とデバイス名・コードの場所に対するすべてのファイルの関数
(Windows。Unix のコードはレビューし、CI でテストしている)、あらゆる種類のクラス・入れ子・数での `json_decode_as()`、
`format()`、暗号化(毎回新しい salt と nonce、定数時間の検査、トークンの種類の間や JWT でのアルゴリズムの取り違えなし)、
範囲の端での `std.time`、`phv run` 以外での `argv` と標準入力。すべてのテストが Windows で、CI の Linux と macOS で通り、
clippy(`-D warnings`)と rustfmt も通る。

依存: `cargo audit`(CI)と、拡張機能・Web サイトの `npm audit --omit=dev` は何も見つけない。新しいクレート:
`chrono-tz`、`phf`、`phf_shared`。`regex`・`regex-automata`・`url`・`ring` はすでに lockfile にあった。

### 残っているリスク

- SQLite のメモリにはプロセス全体で 1 つの上限(512 MB)がある。1 つのスクリプトのメモリ上のデータベースはそのメモリ
  上限までだが、同時に多くのリクエストがあれば上限に届き、それが終わるまで他のリクエストの SQLite が失敗する。
- `tls_cert` と `tls_key` はこのマシンの絶対パスでもよい(証明書はふつうプロジェクトの外にある)。ファイルは PEM として
  読むだけで、中身は表示しない。
- `publish()` が届くのは 1 つのサーバープロセスの WebSocket の接続だけ。
- デモのベースイメージはダイジェストで固定しておらず、アーカイブは同じリリースの `SHA256SUMS` で確かめる(壊れていれば
  分かるが、リリースごと差し替えられたことは分からない)。
- 循環参照の回収はオブジェクトの数で動き、メモリが足りなくなったときには動かない。

### 残存リスク

- 誰も求めていない答えを本当の答えの数ミリ秒後に送る HTTP サーバーでは、その答えを、すでに送り出された次のリクエストが
  残した接続で読むことがある: HTTP/1.1 は答えとリクエストを結び付けない。接続を残すときと取り出すときの確認で残るのはこの間だけ。
- `GET` を処理して答えずに閉じる相手には、`GET` がもう一度届く(閉じられた残した接続での通常の再送で、`GET`・`HEAD`・
  `OPTIONS` だけ)。
- 使われていない残した SQLite の接続はファイルを最長 30 秒開いたままにする: その間 Windows では PHV の外のプログラムから
  名前の変更や削除ができない。
- 部分の共有のしかたが違う構造の `==` は、止まるまでにメモリの上限の約 2 倍に達しうる(比べた組の表が一度に大きくなる)。
- 構文解析はソースの大きさの何倍ものメモリを使う(8 MB の list の要素のファイルは検査の間に約 1.5 GB)。
- 呼び出しのあと、関数のレジスタは引数を持ったまま: 渡した直後に list を変えると写しを作る(時間とメモリは数える)。JIT の
  スタックの予算は最も外側のネイティブの呼び出しから測る。
- テンプレートの見張る状態(`<noscript>`・`<svg>`・`<math>` の中)で、`</` と終了タグの残りの間に呼んだ関数は `phv check` を
  通る。ページは実行時に止まり、ブラウザーには何も届かない。
- Unix の `opened_at` は、開いたファイルとパスを 2 段階で比べる(Windows はハンドルを使う)。
- §22 の残存リスクはそのまま(SQLite のプロセス全体のヒープの上限、ローカルの TLS のパス、1 つのプロセスの中の `publish()`、
  デモのベースイメージのダイジェスト固定なし、数で動く循環参照の回収)。

### 残存リスク

- 読まないクライアントが 1 イベントずつで枠を埋めるほどあると、サーバーがそれらを切るまで(30 秒進まなければ)、読む
  クライアントはイベントを逃す。そのあとはまた開き直す必要があり、そのたびに Open イベントのワーカーを使い、流量制限の
  中に収まる必要がある。
- 同時に動くトランザクションは、コミットするまでに追加した分だけ、100,000 件のジョブの上限を超えうる。
- PostgreSQL・MySQL のセッションのデータベースを共有するサイトどうしは、その上限と最も短い `session_ttl` を共有する。同じ
  名前、または名前のないサイトどうしは、共有の保存先でセッション・流量制限・ジョブを共有する。サイトごとにデータベースか
  `store_namespace` を持つこと。
- 捕まえたバスのメッセージは、送られる前から購読していてまだ受け取っていないプロセスに、60 秒の間はもう一度送れる(Redis
  サーバーに書き込める者だけ)。時計が 60 秒より離れたプロセスどうしは互いのメッセージを捨てる。Redis は遅れすぎた購読者を
  切る(配信は最大 1 回)。
- サーバーの出力は `workers` × `memory_limit_mb` の 2 倍まで達しうる: ページとイベントストリームがそれぞれその枠を持つ。
- セッションをデータベースに置き名前のあるサイトは、アップグレードで訪問者が一度ログアウトし、共有のテーブルに残した
  ジョブは取られない。
- §23 の残存リスクはそのまま。

### 検証

すべての PoC を修正後のビルドで再実行した:
- 読まないイベントストリーム: 32 CPU のホストで 30 個なら 975 MB(3.9 GB)。64 MB の枠では、ページはずっと 200 を返し、
  ページの出力は 0 のまま、読まないものが 10 個や 60 個でも読むクライアントはすべてのイベントを受け取る(80 個では 8 件中
  3 件: R17-28)。
- リテラルの HTML のループは 87 MB で上限に止まる(4.1 GB)。
- `min()`・`max()` は 1.1 秒で止まる(23 秒)。`contains()`・`indexOf()` は 1.1〜1.2 秒(最大 18.8 秒)、`groupBy()` は 1.1 秒
  (15.9 秒)、`E::cases()`・`E::tryFrom()` は 1.1〜1.3 秒(75.9 秒と 2.1 秒)。null を含む `unique()` は 0.13 秒。
- 購読者 10 の集中した送信は送られる(1,800 件中 1,766 件、残りは満杯のキューで捨てた。以前は 76 件)。`/ready` は通信なしで
  回復し、PUBLISH を許されないユーザーでは 503 のまま。送り直しは再起動や `CLIENT KILL` のあとも拒まれ、新しいメッセージは
  届く。
- 名前の違う 2 つのサイトは、1 つの Redis・PostgreSQL・MySQL のデータベースでセッション・流量制限・ジョブを共有しない。
- 200,000 個のスケジュールの `phv check` は 0.3 秒(159 秒)。ジョブの上限は 1 つのトランザクションで守られる。メモリの
  ストアは、あきらめたジョブ 10,000 件のあとも 32 MB(658 MB)。答えないストアでの `enqueue()` はページの上限で返る(10 秒)。
  満杯の上限で拒まれた 200 件が読むテーブルのページは 1,481(260,746)。
- 全角スペースやノーブレークスペースのテンプレートは拒まれる。サーバーのログに生の制御文字はない。隠した変数は大文字
  小文字をどう変えても読めない。`[jobs] dir` と `phv migrate -o` の途中のリンクは拒まれる。

差分チェック: 変わっているが許される構造(空白のない属性、属性の間の `/`、重複した属性、変わったコメントや偽のコメント、
生テキスト・表・frameset の要素、NUL と CR)の 182 個はすべて通り、html5lib はどれでも値をテキストか普通の属性値に置くか、
捨てた。拒むべき場所(イベント属性、`style`、URL、生テキスト、名前、引用符なしの値)の変わった書き方 672 個は拒まれた。
例外は `<a =onclick="` の形の 50 個で、ブラウザーはこの属性を `=onclick` と名付けるので、イベント属性ではない。チェックの
分類は、先に既知の 11 の置き場所で確かめた。

回帰テスト:
- phv_syntax: `only_html_whitespace_separates_attributes`、`log_text_stays_on_one_line`。
- phv_server: `events_count_in_the_output_cap`(小さなウィンドウの HTTP/2 で、読まないクライアント 3 つと読むもの 1 つ)、
  `label_values_stay_on_their_line`、`frames_are_signed_and_checked`、`replayed_frames_are_refused`、
  `publish_reaches_the_other_server_processes` の送り直し、`database_stores_keep_the_same_rules` のほかのサイトの名前空間。
- phv_driver: `literal_html_in_a_loop_stops_at_the_memory_limit`、`builtins_over_long_values_stop_at_the_time_limit`、
  `unique_compares_only_what_it_cannot_hash`、`enum_cases_are_timed`、`enum_lookups_are_timed`、`databases` のほかの
  名前空間のジョブ。
- 設定: `server_variables_are_hidden_from_scripts`、`sites_get_a_namespace_from_their_name`、
  `many_schedules_are_refused_at_once`、`a_linked_jobs_folder_is_refused`。
- そのほか: 流量制限の `namespaces_keep_sites_apart`、ジョブの `what_the_memory_store_keeps_is_bounded`、phv_cli のジャンクションの

### 残存リスク

- プログラム全体の枠のすぐ下のプログラム(1,000,000 トークンのファイル 2 つなど)は、検査に約 415 MB を使いうる。
- 型検査は、ループや `try` の本体を、それを囲むものごとに読み直す。入れ子の上限 500 で抑えられる(100,000 回の代入を
  200 段で囲んで 5 秒)。
- 残りのメモリに走査の一部さえ収まらないときは、古いオブジェクトの循環がスクリプトの終わりまで残る。メモリエラーの前の
  最後の回収は、上限をその 8 分の 1 まで超えうる。
- 使い回す接続の SQLite のメモリは見積もりで、数 KB ずれうる。上限の大きいワーカーがいくつかあると、プロセス全体の
  SQLite の 512 MB にはまだ届きうる(384 MB でキャッシュを手放し始める)。
- スクリプト自身の MySQL のトランザクションの中でキーつきの `enqueue()` をすると、別のトランザクションのキーを、
  スクリプトが動ける間だけ待ちうる。上限の近くでは、空きがあっても最大 1 秒、追加を断ることがある。ほかの追加と並行して
  10,000 件より多く足すトランザクションは、その分だけ上限を超えうる。
- SVG の中で、`<noscript>` 以外の生テキストの要素の終了タグを値が完成させる場合は、`phv check` ではなくページの実行時に
  止める。`<!--` の直後の値は、間に空白が要る。
- エディターが開く文書までの途中にある、共有フォルダーへのディレクトリのリンクは、まだ見に行く(ファイルを開くとき
  エディターがすでにそのホストに接続している)。
- 上で修正したもの以外の §24 の残存リスクは残る。

  コメントも検査で拒否する(生きたリンクが出ていた)。

### 残存リスク

- 重さの上限ちょうどの文は、速いマシンでも時間の上限を約 3 秒超えて動きうる。遅いマシンではさらに長い。上限より重い文
  (値への算術がおよそ 30 列を超えるもの)は拒否するので、分ける必要がある。
- 読むのをやめたストリーミングのクライアントは、最大 10 秒ワーカーを持つ。
- テンプレートの検査は、ブラウザーが受け付けるいくつかのマークアップを拒否するようになった。たとえば `<foreignObject>` の中の
  閉じない HTML 要素、SVG の中のブレイクアウトするタグ、`<annotation-xml>` の中の `<svg>` 以外の要素、要素を開いたまま残す
  SVG の中のループ。SVG の中で `<noscript>` 以外の生テキストの要素の終了タグを値が完成させる場合は、引き続きページの実行時に
  止める。
- スクリプトが最初の型の検索と同じ実行の中でクライアントの型の検索の一部を解放すると、その接続の後の文が、接続が閉じられる
  前に 1 回失敗しうる。
- 鍵セットの一番最初の取得の間に来た並行のリクエストは、すべてそれを待つ。
- 名前空間のないサイトの 1.1.1 と 1.2 のプロセスを並べて動かす間、古いほうは新しいほうが保存したセッションを読まない。
- 上で確かめたもの以外の §25 の残存リスクは残る。
